NOMBRES ACTUALES
----------------

- index.php es la pagina publica actual.
- admin.php es el panel administrador actual.

- editar_contenedor.php edita contenedores.

Referencias antiguas como index_1.php, admin_1.php y preview_contenedor_1.php no deben usarse como nombres canonicos. Si aparecen, deben corregirse a index.php, admin.php y preview_contenedor.php.

REGLA CENTRAL DE CONTENEDORES
-----------------------------

Contenedor = registro en tabla seccion.
Componente = archivo PHP en componentes/{nombre_interno}.php.
Configuracion = tabla seccion_config.
Items repetibles = tabla seccion_item.

El campo seccion.nombre_interno define el archivo esperado del componente.

Ejemplo:

spotify_podcast_home -> componentes/spotify_podcast_home.php

Excepcion actual:

header_principal -> componentes/header.php

Esta excepcion esta en cms_get_component_path().

RENDER PUBLICO
--------------

index.php carga cms_get_site_data(), filtra secciones visibles, respeta orden y llama cms_get_component_path() por cada seccion.

Para que un contenedor aparezca deben cumplirse estas condiciones:

- Existe registro en seccion.
- visible = si.
- estado compatible con render activo.
- Existe componente en componentes/ o fallback real en cms_get_component_path().
- El orden lo ubica donde corresponde.

MENU PUBLICO VS MENU ADMIN
--------------------------

Menu publico:

- Tablas: menus, sub_menus.
- Render: header_principal, actualmente componentes/header.php.
- Pagina: index.php y paginas publicas que incluyen header.
- Visitantes del sitio lo ven en la parte superior.
- Las paginas internas pueden usar sub_menu_paginas y sub_menu_pagina_media.
- Flujo tipico: index.php -> header -> menus/sub_menus -> pagina_submenu.php.

Menu administrador:

- Tablas: admin_menu, admin_submenu.
- Render: includes/admin_layout.php.
- Pagina principal: admin.php.
- Solo sirve para navegacion interna del panel.
- No afecta menus ni sub_menus.

ADMINISTRACION, PERMISOS Y CAMBIO DE CLAVE POR CORREO
-----------------------------------------------------

Diseno admin actual:

- includes/admin_layout.php carga los estilos y scripts administrativos compartidos.
- assets/css/admin.css contiene el estilo base sobrio del panel.
- assets/css/admin_sidebar.css contiene el sidebar oscuro compacto.
- assets/css/admin_tables.css contiene tablas administrativas.
- assets/css/admin_permissions.css contiene matriz y modal de permisos.
- assets/css/admin_dashboard.css contiene estilos extraidos desde admin.php.
- assets/css/admin_contenedores.css contiene estilos extraidos desde editar_contenedor.php.
- assets/js/admin.js contiene utilidades globales.
- assets/js/admin_sidebar.js maneja colapso y submenus.
- assets/js/admin_permissions.js maneja acciones de matriz de permisos.

Regla visual:

- El panel administrador debe usar botones sobrios.
- Evitar gradientes fuertes en Nuevo usuario, Agregar item, Guardar permisos y acciones principales.
- El sitio publico y el menu publico no se modifican por cambios del admin.

Permisos desde usuarios:

- admin_usuarios.php muestra un boton de escudo por usuario.
- El modal permite asignar perfil y revisar/editar la matriz de permisos asociada.
- La base actual no tiene tabla de permisos directos por usuario.
- La asignacion del usuario se guarda en usuario_perfil.
- La matriz se guarda en perfil_permiso_admin, por perfil.
- Editar la matriz desde el modal de un usuario afecta a todos los usuarios con ese perfil.
- Solo id_usuario = 1 puede guardar cambios.
- Usuarios con permiso ver pueden abrir el modal en modo lectura.

Cambio de clave por correo:

- El boton de sobre de admin_usuarios.php llama por AJAX a ajax/enviar_correo_clave.php.
- El endpoint valida permiso editar sobre usuarios.
- Genera reset_token seguro y reset_token_expira.
- Envia el correo con PHPMailer usando includes/mail_helpers.php.
- Las credenciales SMTP se leen desde config/mail.php.
- No hardcodear credenciales SMTP en archivos PHP de negocio.
- cambiar_clave.php valida token, expiracion y guarda nuevas claves con password_hash().

SQL requerido si faltan columnas:

ALTER TABLE usuario
ADD COLUMN reset_token VARCHAR(255) NULL AFTER intento_fallido,
ADD COLUMN reset_token_expira DATETIME NULL AFTER reset_token;

POLITICA GLOBAL DE ARCHIVOS
------------------------------

Documento completo: logica/07_politica_archivos_multimedia.txt.

- assets/ = recursos del sistema (tema, CSS, JS, iconos). No recibe subidas de
  usuarios.
- uploads/ = archivos cargados por usuarios desde el panel, organizados por
  modulo real: uploads/secciones/{nombre_interno}/, uploads/noticias/,
  uploads/eventos/ (+ adjuntos/, media/{id_evento}/), uploads/institucion/,
  uploads/comunicados/, uploads/submenus/{id_sub_menu}/.
- Toda subida nueva usa includes/upload_helpers.php (cms_guardar_archivo,
  cms_validar_imagen, cms_validar_video, cms_validar_adjunto,
  cms_generar_nombre_seguro); includes/cms_helpers.php delega en ese helper
  desde cms_upload_image(), cms_upload_image_payload() y cms_upload_file().
- URLs externas (YouTube, Spotify, Vimeo, Google Maps, etc.) se guardan siempre
  como texto/URL en la base de datos; nunca se copian al servidor.
- La base de datos guarda solo rutas relativas de archivos locales
  ("uploads/..."), nunca rutas absolutas del servidor ni binarios.
- uploads/ NO debe reemplazarse ni eliminarse durante un despliegue en cPanel;
  respaldar base de datos y uploads/ antes de cambios importantes.
- Existen rutas legacy reales en assets/images/*.jpg referenciadas desde
  seccion_item/seccion_config; se mantienen intactas, no se migran
  automaticamente.
