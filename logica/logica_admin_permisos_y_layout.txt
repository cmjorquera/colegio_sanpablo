LOGICA ADMINISTRATIVA: PERMISOS Y LAYOUT

Tablas usadas
- admin_menu: define los modulos principales del sidebar administrativo. Se usa clave, grupo, label, href, icono, orden, visible y estado.
- admin_submenu: define los hijos desplegables de cada admin_menu. Se usa id_admin_menu, clave, label, href, icono, orden, visible y estado.
- perfiles: define perfiles administrativos activos.
- usuario_perfil: asigna uno o mas perfiles reales a cada usuario.
- perfil_permiso_admin: guarda permisos por perfil, tipo_menu ('menu' o 'submenu'), id_menu y columnas puede_ver, puede_crear, puede_editar, puede_eliminar.
- usuario: se mantiene por compatibilidad con rol legacy, login, institucion y datos basicos.

Como se arma el sidebar
- includes/admin_layout.php llama admin_nav_items().
- admin_nav_items() consulta admin_menu activos y visibles.
- Luego consulta admin_submenu activos y visibles, asociandolos a su id_admin_menu.
- Los menus se agrupan por admin_menu.grupo.
- El orden de grupos queda fijo como: PRINCIPAL, GESTION DEL SITIO, SEGURIDAD, ANALITICA, SISTEMA.
- Cada menu/submenu se filtra por permiso puede_ver del perfil real del usuario.
- La opcion activa se detecta por active_panel, script actual y parametro panel.
- Algunas rutas historicas se normalizan sin cambiar la base: calendario -> admin_calendario.php, permisos -> admin_permisos.php, auditoria -> auditoria_log.php, usuarios -> admin_usuarios.php y comunicados -> admin_comunicados.php.
- Los botones inferiores Ver sitio, Cerrar sesion y Colapsar se conservan en el layout.

Como funcionan permisos por perfil
- includes/admin_permissions.php centraliza la resolucion.
- admin_obtener_perfiles_usuario() lee usuario_perfil + perfiles.
- admin_tiene_permiso() busca primero en admin_menu; si la clave no existe como menu, intenta resolverla como admin_submenu. Esto permite que paginas antiguas sigan llamando admin_tiene_permiso('contenedores', ...), aunque contenedores sea submenu.
- admin_tiene_permiso_submenu() fuerza busqueda directa en admin_submenu.
- Super Administrador tiene acceso total por id_usuario = 1, rol legacy super_admin/super_administrador o perfil con nombre Super Administrador.
- Si no existe perfil_permiso_admin se mantiene compatibilidad permisiva.

Acceso a pagina vs acciones internas
- puede_ver controla visibilidad en el sidebar y acceso directo por URL.
- Si el usuario no tiene puede_ver, la pagina redirige al dashboard con el mensaje: "No tienes permiso para acceder a este módulo".
- puede_crear controla botones Nuevo/Crear y POST de creacion.
- puede_editar controla botones Editar, formularios de edicion, switches de estado, switches de visible/publicado y POST de edicion.
- puede_eliminar controla botones Eliminar/Inactivar y POST de eliminacion.
- admin_comunicados.php exige puede_editar para el switch Visible; si el usuario solo puede ver, el switch queda deshabilitado y el POST tambien se bloquea.

- includes/admin_permissions.php: mensajes, perfil visible real, fallback menu/submenu, orden de matriz y prevencion de menu Permisos duplicado.

Modal de items del Carrusel principal
- El modal de creacion/edicion de slides del carrusel ahora diferencia explicitamente entre Tipo de slide: Imagen o Video YouTube.
- Un slide no puede guardar imagen y video YouTube al mismo tiempo. La validacion se aplica en el navegador y tambien en PHP antes de llamar a cms_save_item().
- Si el tipo es Imagen, el campo Video YouTube se oculta, se limpia antes de guardar y el slide exige una imagen nueva o una imagen existente.
- Si el tipo es Video YouTube, el campo Imagen se oculta, la imagen anterior se limpia usando clear_imagen y se exige una URL valida de YouTube.
- La visibilidad del item ya no se edita dentro del modal. Se administra desde las vistas Listado/Tarjetas mediante el switch Visible; el modal conserva un campo oculto para no cambiar accidentalmente el valor actual.
- El modal usa backdrop estatico y keyboard false, por lo que no se cierra al hacer clic fuera ni con Escape. Solo se cierra con X o Cerrar.
- Se reorganizo el modal en dos columnas: datos del slide a la izquierda y recurso/vista previa a la derecha.
- Se agrego vista previa del recurso: miniatura de imagen actual/seleccionada o identificacion del video YouTube detectado.
- No se crearon tablas ni columnas nuevas y no se modifico el render publico del carrusel.
