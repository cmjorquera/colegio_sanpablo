LOGICA DEL MENU PUBLICO
=======================

QUE ES
------

El menu publico es el menu superior visible para los visitantes del sitio.

No es el menu lateral del administrador.

TABLAS
------

menus
Define las opciones principales del menu publico.

Campos relevantes:

- id_menu
- nombre
- url
- icono
- orden
- estado

sub_menus
Define opciones hijas o desplegables de menus.

Campos relevantes:

- id_sub_menu
- id_menu
- nombre
- url
- icono
- orden
- estado

sub_menu_paginas
Existe en la base actual y guarda contenido editorial para paginas internas asociadas a submenus.

sub_menu_pagina_media
Existe en la base actual y guarda imagenes o multimedia de esas paginas internas.

ARCHIVOS INVOLUCRADOS
---------------------

index.php
Pagina publica principal. Carga el contenedor header_principal como parte de la lista de secciones visibles.

componentes/header.php
Componente real actual que renderiza el menu publico superior. Usa $arrMenus y $arrSubs.

includes/cms_helpers.php
cms_get_site_data() carga menus activos y submenus activos. cms_get_component_path('header_principal') resuelve hacia componentes/header.php.

pagina_submenu.php
Pagina publica para submenus internos. Carga header y footer, lee el submenu por id y muestra contenido desde sub_menu_paginas y sub_menu_pagina_media cuando existe.

FLUJO VISITANTE
---------------

1. El visitante abre index.php.
2. index.php carga datos del sitio.
3. index.php renderiza el contenedor header_principal.
4. cms_get_component_path('header_principal') devuelve componentes/header.php.
5. componentes/header.php recorre menus y sub_menus.
6. El visitante ve el menu superior.
7. En menus tematicos, click padre abre /ruta y click hijo interno /ruta#slug-ID.
   /pagina/ID (pagina_submenu.php?id=ID) conserva el acceso individual historico.

REGLAS IMPORTANTES
------------------

- menus = menu principal publico.
- sub_menus = opciones desplegables publicas.
- No confundir con admin_menu.
- No confundir con admin_submenu.
- El menu publico se renderiza en el header del sitio.
- Los submenus internos conservan /pagina/ID como URL individual; el header puede
  enlazar su seccion en la pagina tematica del padre, sin eliminar la individual.
- Las paginas de submenu usan sub_menu_paginas y sub_menu_pagina_media cuando existen.

DIFERENCIA CON CONTENEDORES
---------------------------

El menu publico no es un contenedor independiente llamado menu_principal. En la base actual, el header_principal es el contenedor visual que muestra el menu usando menus y sub_menus.

El helper cms_remove_legacy_menu_principal_section() elimina el contenedor legacy menu_principal si aparece.


URLS AMIGABLES Y HEADER RESPONSIVE
---------------------------------
El sitio se publica en la raiz del dominio (Plesk: /httpdocs). Se mantienen los
archivos PHP y las tablas actuales; no se renombran archivos ni se actualiza SQL.
.htaccess conserva DirectoryIndex index.php, desactiva MultiViews y utiliza
mod_rewrite de Apache 2.4. El hosting debe permitir estas directivas en .htaccess.
Antes de reescribir, las condiciones -f/-d dejan pasar archivos y directorios
fisicos. No hay un fallback generico hacia index.php: rutas desconocidas quedan
con 404. Desde la generalizacion, un slug desconocido llega al controlador y
recibe 404; no se envia a index.php. assets, uploads, api, ajax, includes, PHPMailer, archivos PHP
internos y descargables conservan sus rutas. uploads/.htaccess sigue intacto.

Relacion URL publica -> archivo existente:
/                         -> index.php
/admin                    -> admin.php
/noticias                 -> noticias.php
/noticia/ID               -> noticia_detalle.php?id=ID
/comunicados              -> comunicados.php (conserva page, categoria y q)
/calendario               -> index.php, con desplazamiento al bloque existente
                            calendario-eventos-home; no existe calendario.php
/evento/ID                -> evento_detalle.php?id_evento=ID
/evento/item/ID            -> evento_detalle.php?id_item=ID (compatibilidad legacy)
/pagina/ID                -> pagina_submenu.php?id=ID
/feriado/ID               -> feriado_detalle.php?id_calendario=ID
/feriado/fecha/AAAA-MM-DD  -> feriado_detalle.php?fecha=AAAA-MM-DD

Las reglas usan END para evitar nuevas pasadas de reescritura; QSA en detalles
conserva parametros adicionales. /admin/ se normaliza a /admin con respuesta 308.
Los PHP antiguos siguen accesibles: no hay redireccion global que afecte POST,
fetch o AJAX. todas_noticias.php conserva su redireccion 301, ahora a /noticias.

includes/public_routes.php define cms_public_url(), cargado por cms_helpers.php.
Convierte solo navegacion conocida, conserva filtros y fragmentos, no modifica
URLs externas ni endpoints. cms_submenu_public_url() usa /pagina/ID como fallback.
Header, footer, enlaces de noticias/eventos, botones publicos y el JSON del
calendario generan navegacion amigable. El endpoint calendario_eventos_json.php
conserva su nombre; solo cambian las URLs publicas que devuelve.
Las vistas publicas y el login usan base href="/" para que recursos relativos,
imagenes configuradas, uploads, formularios y fetch resuelvan desde la raiz,
tambien bajo /noticia/ID o /pagina/ID. Los enlaces a bloques del inicio son
referencias al inicio; las rutas internas del panel no se migran.

Header: componentes/header.php conserva logo, colores, tipografia, dropdowns y
el offcanvas Bootstrap existente. sp-header-row/sp-header-actions usan flex sin
wrap; debajo de 1600 px se ocultan menu horizontal y boton de escritorio y se
muestra hamburguesa. La medicion del menu actual arrojo unos 1540 px necesarios;
1600 px deja margen. Ya no se usan las clases d-xl del anterior limite de 1200.
El menu movil usa los mismos arrMenus/arrSubs, sin perder elementos o submenus.
Evento y feriado reutilizan este mismo header en lugar de copias sin hamburguesa.

includes/public_floating_actions.php centraliza el grupo existente de cantina y
comunicados y agrega Inscripciones arriba, solamente en modo hamburguesa. El
grupo se renderiza una sola vez, desde el header o como fallback desde index.php.
Inscripciones usa el mismo texto y url_boton_principal de institucion que el
boton de escritorio; no se inventa ni se guarda otro destino.
Los botones usan diametro 58 px (54 px bajo 768), separacion 14 px (12 px en
movil), mismo margen, sombra y expansion suave al hover/foco. Inscripciones usa
un icono de formulario y su texto aparece al expandirse. El control hamburguesa
tiene area tactil minima de 44 px. Todo el CSS del header/grupo flotante esta en
assets/css/pages/colegiosanpablo.css; se extrajo el CSS previo de index.php.
La identidad dinamica se transmite mediante variables CSS, sin bloques style
nuevos. El modal publico no recupera ningun acceso ADMINISTRADOR.

No se modifican class/conexion.php, class/conexion_local.php, credenciales,
PHPMailer o config/mail.php. La configuracion local sigue fuera de Git.


PAGINAS TEMATICAS: NAVEGACION GENERICA (2026-10-05)
--------------------------------------------------
Los menus activos con hijos internos usan pagina_menu.php. Biblioteca ya no es
una excepcion por id_menu: comparte controlador, helpers, CSS/JS y galerias.
Click padre abre pagina; dropdown sigue disponible por hover/focus y offcanvas.
Hijos internos enlazan a /ruta-menu#slug-ID; destinos externos/especiales conservan
su URL. /pagina/ID y biblioteca.php siguen disponibles por compatibilidad.

URLs: menus.url vacia/'#' genera slug desde nombre. Una ruta local de un segmento
permite fijar la URL desde el campo existente. Slug duplicado/reservado/ocupado
usa /menu/ID si era generado. Enlaces externos, archivos, destinos especiales y
menus sin hijos internos mantienen su comportamiento; no se escriben URLs en BD.
Mi San Pablo, mixto, reune contenido interno y conserva portales externos en la
navegacion. Inicio conserva la URL externa registrada. Se habilitan dinamicamente
los restantes menus compatibles sin lista de IDs ni reglas Apache por nombre.

.htaccess conserva las rutas especificas y -f/-d; al final agrega los patrones
/menu/ID y /slug a pagina_menu.php. Parametros route_id/route_slug sustituyen la
query para evitar alterar la ruta. Desconocidos/inactivos: 404; fallo: 503 generico.
includes/public_routes.php comparte politica de URL/elegibilidad con header y
resolver. Anchors usan nombre normalizado + id_sub_menu; pagina-menu.js resuelve
fragments antiguos por ID al renombrar y solo intercepta links de la pagina actual.
Documentacion completa y pruebas: logica/logica_menus_submenus_paginas.txt.
