# CONTENEDOR calendario_eventos_home

Este contenedor pertenece al home y muestra una sección visual de calendario institucional junto con próximos eventos.

Archivo del componente:

componentes/calendario_eventos_home_1.php

nombre_interno = calendario_eventos_home

titulo_bloque

url_boton
cantidad_items

Conceptos obligatorios:

calendario = base de dias, feriados, fines de semana y dias institucionales.
eventos = actividades institucionales cargables manualmente o por Excel.

Los eventos reales se guardan en la tabla eventos. La tabla seccion_item queda como compatibilidad del CMS y como fallback visual cuando aun no existen eventos cargados en la tabla eventos.

Campos legacy usados en seccion_item cuando se use el fallback:

etiqueta representa la categoría del evento.
titulo representa el título del evento.

Regla de detalle legacy:

Si boton_1_url tiene valor, se usa boton_1_url.

evento_detalle.php?id_item=ID

evento_detalle.php?id_evento=ID

# ADMINISTRACIÓN DE EVENTOS Y CARGA MASIVA

El contenedor calendario_eventos_home mantiene su definición visual dentro del CMS de contenedores, pero los eventos reales se administran desde la tabla eventos.

La tabla seccion sigue definiendo el contenedor, seccion_config sigue guardando configuraciones del bloque y seccion_item queda solo como compatibilidad visual o fallback. El calendario publico debe mostrar siempre tanto feriados/dias especiales desde calendario como eventos desde eventos.

Los eventos pueden crearse manualmente desde la pestaña Items del contenedor calendario_eventos_home mediante el botón Agregar evento.

Tambien pueden cargarse masivamente desde Excel o CSV desde la misma pestaña Items.

La plantilla se descarga desde el admin con el boton Descargar plantilla Excel. La carga masiva no incluye imagenes ni archivos adjuntos. Si PHP no tiene ZipArchive, el sistema puede entregar un Excel XML .xls compatible con Excel manteniendo las hojas EVENTOS y AYUDA.

La plantilla Excel debe tener:

Hoja EVENTOS:
fila 1 titulo institucional.
fila 2 nombre de institucion desde tabla institucion.
fila 3 Descargado por y Fecha descarga. El usuario se obtiene desde SESSION id_usuario y tabla usuario.
fila 5 encabezados reales.

Hoja AYUDA:
documentacion institucional de columnas, formatos, ejemplos, errores comunes, reglas de fechas y reglas de horas.

Campos mínimos obligatorios para carga o creación:

titulo
fecha_inicio

Campos de la plantilla:

titulo
descripcion_corta
descripcion
fecha_inicio
fecha_termino
hora_inicio
hora_termino
categoria
ubicacion
color
destacado
visible
orden

El campo estado no forma parte de la plantilla Excel ni del preview. Para cargas masivas se usa el valor por defecto publicado mediante la normalizacion del CMS.

Reglas:

fecha_inicio debe venir como yyyy-mm-dd.
hora_inicio debe venir como HH:mm.
visible y destacado usan 1 o 0.
Si fecha_termino viene vacía, se usa fecha_inicio.
Si color viene vacío, se asigna según categoría.

Flujo obligatorio de carga masiva:

1. Usuario sube Excel o CSV.
2. Sistema parsea y valida.
3. Se muestra una tabla preview.
4. Cada fila tiene checkbox individual.
5. Existe checkbox superior Seleccionar todos.
6. Solo filas marcadas se importan.
7. La insercion real ocurre al confirmar con Cargar eventos seleccionados.

La subida del archivo nunca debe insertar automaticamente eventos.

REGLA IMPORTANTE SOBRE CALENDARIO VS EVENTOS:

La tabla calendario contiene los dias del calendario institucional. Incluye fecha, es_feriado, nombre_feriado, tipo, color, fines de semana y dias habiles. Estos registros no se cargan masivamente desde Excel y no se editan desde el flujo de eventos.

La tabla eventos contiene eventos institucionales reales. Este flujo de plantilla, preview con checkbox e importacion confirmada trabaja solo con eventos.

componentes/calendario_eventos_home_1.php debe mostrar ambos tipos de informacion:

feriados y dias especiales desde calendario.
eventos cargados desde eventos.

Los feriados existentes en calendario deben aparecer aunque no existan eventos cargados.

La carga masiva Excel no debe insertar ni modificar registros en calendario.

Los eventos publicados y visibles se muestran en el calendario público del home.

El calendario público debe renderizarse en la página principal:

index_1.php#calendario-eventos-home

No apuntar el calendario ni sus botones de retorno a colegiosanpablo.php.

El detalle público se abre en:

Desde evento_detalle.php los enlaces de volver deben regresar a:
