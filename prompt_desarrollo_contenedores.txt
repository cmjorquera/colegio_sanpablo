# CONTENEDOR calendario_eventos_home

Este contenedor pertenece al home y muestra una sección visual de calendario institucional junto con próximos eventos.

Archivo del componente:

componentes/calendario_eventos_home_1.php

La sección se define en la tabla seccion con:

nombre_interno = calendario_eventos_home
tipo_seccion = events
variante = calendario_lista

Usa seccion_config para administrar textos y comportamiento general del bloque:

titulo_bloque
subtitulo_bloque
texto_boton
url_boton
cantidad_items
mes_titulo

Los eventos reales se guardan en la tabla eventos. La tabla seccion_item queda como compatibilidad del CMS y como fallback visual cuando aun no existen eventos cargados en la tabla eventos.

Campos legacy usados en seccion_item cuando se use el fallback:

etiqueta representa la categoría del evento.
titulo representa el título del evento.
subtitulo representa la hora del evento.
descripcion representa una descripción corta.
imagen representa la imagen del evento.
fecha_publicacion representa la fecha del evento.
boton_1_texto representa el texto opcional del botón.
boton_1_url o url pueden apuntar al detalle del evento.

Regla de detalle legacy:

Si boton_1_url tiene valor, se usa boton_1_url.
Si boton_1_url está vacío y url tiene valor, se usa url.
Si ambos están vacíos, se usa:

evento_detalle.php?id_item=ID

Para eventos reales de la tabla eventos, el detalle publico usa:

evento_detalle.php?id_evento=ID

# ADMINISTRACIÓN DE EVENTOS Y CARGA MASIVA

El contenedor calendario_eventos_home mantiene su definición visual dentro del CMS de contenedores, pero los eventos reales se administran desde la tabla eventos.

La tabla seccion sigue definiendo el contenedor, seccion_config sigue guardando configuraciones del bloque y seccion_item queda solo como compatibilidad visual o fallback. El calendario público debe alimentarse preferentemente desde eventos.

Los eventos pueden crearse manualmente desde la pestaña Items del contenedor calendario_eventos_home mediante el botón Agregar evento.

También pueden cargarse masivamente desde Excel o CSV desde la misma pestaña Items.

La plantilla se descarga desde el admin con el botón Descargar plantilla Excel. La carga masiva no incluye imágenes ni archivos adjuntos.

Campos mínimos obligatorios para carga o creación:

titulo
fecha_inicio

Campos de la plantilla:

titulo
descripcion_corta
descripcion
fecha_inicio
fecha_termino
hora_inicio
hora_termino
categoria
ubicacion
color
destacado
visible
estado
orden

Reglas:

fecha_inicio debe venir como yyyy-mm-dd.
hora_inicio debe venir como HH:mm.
estado permitido: borrador, publicado, oculto, cancelado.
visible y destacado usan 1 o 0.
Si fecha_termino viene vacía, se usa fecha_inicio.
Si estado viene vacío, se usa publicado.
Si color viene vacío, se asigna según categoría.

Los eventos publicados y visibles se muestran en el calendario público del home.

El calendario público debe renderizarse en la página principal:

index_1.php#calendario-eventos-home

No apuntar el calendario ni sus botones de retorno a colegiosanpablo.php.

El detalle público se abre en:

evento_detalle.php?id_evento=X

Desde evento_detalle.php los enlaces de volver deben regresar a:

index_1.php#calendario-eventos-home

La tabla calendario complementa el calendario visual con feriados, fines de semana, nombre_feriado y color del feriado cuando esas columnas existan en la base real.

La base actual incluye además la tabla:

dia_semana

Esta tabla define los nombres de lunes a domingo, orden y si corresponde a fin de semana. El calendario público puede usar los datos ya denormalizados de calendario, pero no se debe olvidar que dia_semana forma parte del modelo real del calendario institucional.

Para que eventos del mes actual no desaparezcan cuando la fecha exacta ya pasó, el componente debe buscar eventos desde el primer día del mes actual cuando no encuentre eventos en el mes configurado. Ejemplo: si hoy es 2026-05-23 y existe un evento 2026-05-22, debe seguir mostrándose dentro del calendario de Mayo 2026.
