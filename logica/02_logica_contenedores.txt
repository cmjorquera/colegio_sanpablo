LOGICA DE CONTENEDORES
======================

REGLA PRINCIPAL
---------------

Contenedor = registro en la tabla seccion.
Componente = archivo PHP en componentes/{nombre_interno}.php.
Configuracion del contenedor = registros en seccion_config.
Items repetibles del contenedor = registros en seccion_item.

La carpeta activa para render publico es componentes/. La carpeta contenedores/ queda como referencia legacy y no debe considerarse carpeta activa del CMS.

QUE ES UN CONTENEDOR
--------------------

Un contenedor es un bloque visual administrable del sitio publico: topbar, header, hero, noticias, calendario de eventos, galeria, podcast, FAQ, about, estadisticas, footer o modal.

Cada contenedor existe primero como registro en seccion. Luego puede tener configuraciones y/o items. Finalmente necesita un componente PHP que se encargue de pintar el HTML publico.

TABLA QUE LO DEFINE
-------------------

La tabla seccion define la existencia del contenedor.

Campos importantes:

- id_seccion: identificador interno del contenedor.
- id_institucion: institucion a la que pertenece.
- nombre_interno: nombre logico del contenedor y nombre de archivo esperado.
- titulo_admin: nombre mostrado en el panel.
- tipo_seccion: tipo funcional, por ejemplo header, carousel, news, events, gallery, podcast.
- variante: variante visual o de comportamiento.
- visible: si/no; index.php solo renderiza las secciones visibles.
- estado: activo, inactivo o borrador.
- editable: si/no; indica si se puede administrar.
- usa_config: si/no; indica si usa seccion_config.
- usa_items: si/no; indica si usa seccion_item.
- orden: posicion de render en index.php.

SECCION_CONFIG
--------------

seccion_config guarda pares clave/valor por contenedor.

Ejemplos reales:

- noticias_home: titulo_bloque, subtitulo_bloque, texto_boton, url_boton.
- calendario_eventos_home: titulo_bloque, subtitulo_bloque, cantidad_items.
- spotify_podcast_home: titulo_bloque, descripcion_bloque, url_boton, mostrar_episodios.
- modal_informativo: mostrar, delay_ms, color_boton.

SECCION_ITEM
------------

seccion_item guarda elementos repetibles del contenedor: slides, noticias, preguntas frecuentes, imagenes de galeria, episodios de podcast, redes sociales, etc.

Campos frecuentes:

- id_seccion: relacion con seccion.
- id_categoria: relacion opcional con categoria_noticia en noticias.
- etiqueta: tipo interno del item o categoria visual.
- titulo, subtitulo, descripcion.
- imagen, imagen_mobile, video_youtube.
- boton_1_texto, boton_1_url, boton_2_texto, boton_2_url.
- url.
- fecha_publicacion.
- visible.
- orden.

COMPONENTES/{NOMBRE_INTERNO}.PHP
--------------------------------

El archivo del componente toma los datos ya cargados por index.php:

- $institution
- $sectionConfigsMap
- $sectionItemsMap
- $categoriesById
- $arrMenus
- $arrSubs
- $db cuando corresponde

La regla base es que seccion.nombre_interno define el archivo esperado:

spotify_podcast_home -> componentes/spotify_podcast_home.php

Excepcion real actual:

header_principal -> componentes/header.php

Esta excepcion esta definida en cms_get_component_path().

COMO INDEX.PHP CARGA LOS CONTENEDORES
-------------------------------------

1. Incluye includes/cms_helpers.php.
2. Abre conexion con cms_get_connection().
3. Obtiene datos con cms_get_site_data().
4. Toma site.sections y deja solo visible = si.
5. Recorre los contenedores en orden.
6. Lee seccion.nombre_interno.
7. Llama cms_get_component_path(nombre_interno).
8. Si existe archivo de componente, lo incluye.

QUE HACE CMS_GET_COMPONENT_PATH()
---------------------------------

cms_get_component_path() recibe el nombre interno del contenedor y busca el archivo PHP correspondiente en componentes/.

Primero intenta:

componentes/{nombre_interno}.php

Luego aplica fallbacks definidos en el helper. En la base real actual:

header_principal -> componentes/header.php

Si no encuentra archivo, retorna null. En index.php simplemente no se renderiza ese contenedor. En preview_contenedor.php se muestra una advertencia.

PASOS PARA CREAR UN CONTENEDOR NUEVO
------------------------------------

1. Crear registro en seccion.
2. Definir nombre_interno con un nombre unico y estable.
3. Agregar configuraciones en seccion_config si el componente necesita textos, switches o URLs generales.
4. Agregar items en seccion_item si el componente muestra elementos repetibles.
5. Crear componentes/{nombre_interno}.php.
6. Usar cfg() o cms_cfg() para leer configuraciones.
7. Usar $sectionItemsMap[nombre_interno] para leer items.
8. Verificar en admin.php?panel=contenedores.
9. Editar desde editar_contenedor.php?id=ID.
10. Verificar en index.php.

REGLA DE ARCHIVOS DE UN CONTENEDOR
-----------------------------------

Las imagenes (y video/adjunto cuando el contenedor lo permite) de un item de
seccion_item se guardan como archivo fisico en
uploads/secciones/{nombre_interno}/, salvo dos excepciones reales:

- Contenedores con tipo_seccion = 'news' (noticias_home): sus imagenes van a
  uploads/noticias/, no a uploads/secciones/noticias_home/.
- Paginas de submenu (sub_menu_paginas / sub_menu_pagina_media): usan
  uploads/submenus/{id_sub_menu}/.

La base de datos (seccion_item, seccion_config, sub_menu_paginas) guarda solo la
ruta relativa del archivo o, si el contenido es un enlace de YouTube/Spotify u
otra URL externa, la URL completa en el campo correspondiente (por ejemplo
seccion_item.video_youtube). Nunca se guarda el archivo binario en la base de
datos ni se copia un video/audio externo al servidor.

La subida real se resuelve en includes/cms_helpers.php a traves de
cms_upload_image(), cms_upload_image_payload() y cms_upload_file(), que a su vez
delegan en cms_guardar_archivo() de includes/upload_helpers.php. Detalle completo
de la politica de archivos en logica/07_politica_archivos_multimedia.txt.

ERRORES A EVITAR
----------------

- Crear solo el archivo PHP sin registro en seccion.
- Crear registro en seccion con nombre_interno distinto al archivo.
- Usar contenedores/ como carpeta activa.
- Usar index_1.php, admin_1.php o preview_contenedor_1.php como nombres actuales.
- Confundir seccion_item de noticias con una tabla noticia: en esta base las noticias del home salen de seccion_item.
- Confundir menu publico con menu administrador.
- Ignorar visible, estado y orden al revisar por que algo no aparece.


MODAL INFORMATIVO: CARGA Y DIAGNOSTICO (2026-10-05)
-------------------------------------------------
- cms_get_site_data() construye los mapas por nombre_interno. index.php incluye
  modal_informativo solo si seccion.visible = 'si' y estado = 'activo'. Los
  valores reales son si/no y activo/inactivo, no los numeros 1/0.
- componentes/modal_informativo.php necesita ademas un seccion_item visible
  ('si') con titulo, descripcion o imagen. Activar el contenedor no activa
  automaticamente sus items. Se usa el primer item visible con contenido.
- Es un modal propio, no Bootstrap: hidden + aria-hidden inicialmente;
  .is-open lo muestra, backdrop interno y z-index 99990. No usa .show,
  cookies ni sessionStorage.
- CSS: assets/css/pages/modal_informativo.css. JS independiente:
  assets/js/modal_informativo.js, cargado con defer y con soporte para carga
  posterior a DOMContentLoaded. Cada nodo se inicializa una sola vez.
- seccion_config.mostrar: siempre ignora la marca; una_vez (valor por defecto)
  consulta localStorage. delay_ms controla el retraso (por defecto 650 ms).
- Clave: sp_info_modal_seen_ + los primeros 14 caracteres SHA1 de titulo,
  descripcion, imagen, texto y URL del boton, en ese orden. No se cambio el
  hash ni la regla. Cerrar, pulsar el boton o Escape guarda '1'; abrir no lo
  guarda. Cambiar ese contenido genera otra clave y permite verlo nuevamente.
  Recargar o Ctrl+F5 no borra localStorage. Si el almacenamiento esta bloqueado,
  se permite mostrar el modal en esa visita.
- Defecto corregido: la vista previa usaba la misma clave del sitio publico.
  Cerrar el preview podia impedir verlo despues en la portada del mismo origen.
  data-preview se determina por SCRIPT_NAME=preview_contenedor.php. Ahora el
  preview muestra el contenido sin leer ni escribir la marca del visitante.
  Las marcas anteriores no se borran automaticamente: podrian representar un
  cierre real del visitante y no se puede distinguir su origen retrospectivo.
- El error getTotalLength del template no era la causa del bloqueo del modal:
  en Chrome, con el codigo original, coexistian la excepcion y el modal abierto.
  El listener del modal se registra por separado antes de ejecutar script.js.
  La excepcion si interrumpia el final de ese script, incluido WOW.
- Si vuelve a fallar: primero buscar [data-sp-info-modal] en el HTML recibido.
  Si falta, revisar estado/visible del contenedor, visible/contenido del item y
  version desplegada. Si existe, revisar data-mode, data-hash, data-delay y SOLO
  su clave localStorage. Comprobar los nuevos CSS/JS con HTTP 200, is-open,
  hidden y consola. No borrar todo el almacenamiento ni cambiar a siempre
  como solucion general. Comprobar tambien sin extensiones.
- La lectura HTTP de paginaweb.sanpablo.edu.uy en esta revision no contenia el
  modal e incluia el antiguo acceso administrativo en el encabezado. No prueba
  la configuracion actual de QA ni que estos cambios esten desplegados.
  El parpadeo reportado no se reprodujo; su causa exacta sigue sin confirmarse.
- content-youtube-embed.js no existe en este repositorio. Para clasificar el
  error TrustedHTML hace falta la URL completa del stack: chrome-extension://
  identifica una extension; una URL de terceros identifica ese recurso/frame.
  No se atribuye a YouTube solamente por el nombre ni se debilita CSP.
  powerPreference es una advertencia del navegador; su emisor se verifica en
  el stack. No se agregan capturas globales para silenciar errores.
